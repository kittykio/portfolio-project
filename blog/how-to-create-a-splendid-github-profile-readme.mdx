A profile README should help someone understand what you build and choose a useful next link. A wall of badges can look active while saying little about your work.

## Create the correct repository

For a personal GitHub account named `example-user`, create a public repository named `example-user` and add a nonempty `README.md` at its root. These requirements are described in [GitHub's profile README documentation](https://docs.github.com/en/account-and-profile/how-tos/profile-customization/managing-your-profile-readme). A similarly named repository or a README inside a subfolder will not serve the same purpose.

<Highlight color="lemon">Lead with the work you want readers to understand, then link to evidence they can inspect.</Highlight>

## Use a short structure

This is an illustrative template; replace the project descriptions and example URLs with real work before publishing.

```markdown
# Hi, I'm Kiki

I build web applications with clear interfaces and dependable services.

## Selected work
- [Queue application](https://example.com/queue): booking and status updates.
  I designed the cancellation flow and tested duplicate submissions.
- [Creative editor](https://example.com/editor): interactive poster tools.
  I focused on keyboard access and export quality.

## Currently learning
Testing recovery paths in applications with background jobs.

## Find me
[Portfolio](https://example.com)
```

A concrete contribution is more informative than a long list of tools. Name the problem, your responsibility, and a result you can substantiate. Do not invent usage numbers or disclose confidential client details to make a project sound impressive.

## Choose links that remain useful

Link to a working demo and readable repository when available. If a project is private, explain the general problem and your contribution without implying the source is public. Keep contact details intentional; anything in this repository is public.

<Underline>The README is an introduction, not a second copy of every repository.</Underline> Use pinned repositories for the next layer of detail, and keep setup instructions in each project's own README.

## Treat widgets as optional dependencies

External statistics images can fail, change terms, or omit private work. Give meaningful alt text and keep the profile understandable without them. Contribution totals are not a reliable measure of engineering quality.

If an action updates the README, restrict its permissions and update only a clearly delimited section. Test the change on a branch so automation cannot casually overwrite hand-written content.

Before finishing, open the profile on a narrow screen, follow every link while signed out, and check that the first few lines answer who you are and what you make.

<RainbowHighlight block>A memorable profile makes a few real contributions easy to understand and easy to explore.</RainbowHighlight>

A static server sends files. A mock API returns test data. A framework development server also compiles and runs application code. Choosing the right one avoids debugging a tool that cannot execute your project.

## Serve a static page

Create a directory containing only public demo files, then start Python 3 from that directory:

```bash
python3 -m http.server 8080 --bind 127.0.0.1
```

On Windows, `py -3` may be your Python launcher. Open `http://127.0.0.1:8080`. A directory containing `index.html` will display it; otherwise a listing may appear. This is a development convenience, not a production server, as the [Python documentation](https://docs.python.org/3/library/http.server.html) explains.

<Highlight color="flame">Serve a dedicated demo directory, not your home folder or a repository containing secrets. A static server does not know which files are private.</Highlight>

Binding to `127.0.0.1` restricts access to this machine. It does not make unsafe files appropriate to serve. A phone cannot reach your computer through the phone's own localhost.

## Give a frontend a predictable API

For an isolated tutorial fixture, this example deliberately uses JSON Server 0.17.4. Its CLI differs from newer releases; see the [versioned README](https://github.com/typicode/json-server/tree/v0.17.4).

Create `db.json`:

```json
{ "users": [{ "id": 1, "name": "Aki" }] }
```

Then run:

```bash
npx json-server@0.17.4 --watch db.json --host 127.0.0.1 --port 8081
```

Open `http://127.0.0.1:8081/users`. Expect an array with Aki's record. A mock can support CRUD experiments, but cannot establish that production authorization, transactions, or validation work. Use disposable data; writes can change the fixture.

## Run framework applications with their own command

For a Next.js, Vite, or other framework project, inspect `package.json` and run its documented development script. Python's server cannot compile TSX or execute a Next.js route handler. A frontend on port 8080 calling an API on 8081 also crosses an origin boundary; inspect CORS errors rather than disabling browser security.

<Highlight color="lemon">Confirm the URL, expected response, and server type before changing application code.</Highlight>

## Finish the session

Stop the foreground server with Ctrl–C. If a port is busy, identify its owning process or choose a free port; do not terminate unrelated processes indiscriminately. If changes appear stale, inspect the Network panel and reload before assuming the build failed.

<RainbowHighlight block>Match the server to the job, expose only demo data, and stop it when the session ends.</RainbowHighlight>

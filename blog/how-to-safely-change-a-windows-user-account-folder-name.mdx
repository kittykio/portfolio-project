Changing the name shown at sign-in does not necessarily change the directory under `C:\Users`. Applications may already store that directory in settings, scheduled tasks, and development environments.

<Highlight color="flame">Do not rename an active profile directory or apply an old registry workaround to Windows 10 or 11. Microsoft explicitly warns against extending its older workaround to those versions.</Highlight>

See [Microsoft's profile-path guidance](https://learn.microsoft.com/en-us/previous-versions/troubleshoot/windows-client/renaming-user-account-not-change-profile-path). Changing privileges or stopping processes does not repair every stored path. A new account with a verified migration is a more manageable approach.

## Decide whether the path needs changing

If only the sign-in name is wrong, change the account's display name and leave its folder alone. If a development tool cannot handle your current path, first see whether moving the repository to a simple location such as `C:\dev` solves that specific problem.

For a genuinely new profile, back up your files and confirm you can sign in to another administrator account. On a managed computer, follow your organization's account policy.

## Create and inspect the new profile

1. In Settings, open Accounts and the section for other users; the wording varies by Windows version.
2. Create a local account with the desired simple account name. Avoid assuming a Microsoft account's display name will produce a particular directory name.
3. Sign in once to initialize the profile.
4. In PowerShell, run `$env:USERPROFILE` and confirm the actual path before migrating anything.

<Underline>Verify the destination before investing in the migration.</Underline> Keep the old account available while you test the replacement.

## Move data, then rebuild application settings

Copy documents and projects rather than the entire profile. Do not overwrite the new profile's registry files or blindly merge `AppData`. Export application settings through supported tools, reinstall applications when necessary, and reconnect cloud storage after checking its sync state.

For development work, preserve uncommitted files and ignored configuration securely. Recreate virtual environments, reinstall dependencies, and inspect shell profiles and scheduled tasks for the old path. A copied environment can contain absolute references even when its files appear intact.

## Confirm the new account is usable

Open representative documents, start a project, test required sign-ins, and confirm cloud files are available. Check ownership and permissions if files are inaccessible; do not grant broad access to everyone as a shortcut. Retain a verified backup before considering removal of the old account, which is a separate destructive step.

<RainbowHighlight block>Change a display name when that is enough; migrate and verify a new profile when the directory itself must change.</RainbowHighlight>

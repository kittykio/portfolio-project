WSL 2 runs a Linux kernel in a managed lightweight virtual machine. It is convenient for Linux development on Windows, but it does not remove virtualization or make Windows and Linux filesystems identical.

## Install and confirm the version

Follow [Microsoft's WSL installation requirements](https://learn.microsoft.com/en-us/windows/wsl/install). On a supported Windows system, open an administrator PowerShell and run:

```plaintext
wsl --install
```

Restart if requested, launch the installed distribution, and create its Linux user. Back in PowerShell, inspect the result:

```plaintext
wsl --list --verbose
wsl --status
```

Confirm the distribution shows version 2. Setting `wsl --set-default-version 2` controls future installations; it does not convert every existing distribution. If installation fails, investigate the reported Windows feature, update, or virtualization requirement before repeating commands.

## Keep Linux work with Linux tools

Inside the distribution, create a projects directory:

```bash
mkdir -p ~/projects
cd ~/projects
```

Clone Linux-oriented projects there and install dependencies using the Linux runtime. Windows drives are accessible under paths such as `/mnt/c`, but crossing filesystems can affect performance and permissions. Microsoft explains the tradeoffs in its [WSL filesystem guide](https://learn.microsoft.com/en-us/windows/wsl/filesystems).

<Highlight color="lemon">Keep a project's runtime, dependencies, and working tree in the same environment whenever possible.</Highlight>

Do not share one `node_modules` directory or Python virtual environment between Windows and Linux. Native packages and executable paths can differ. Use an editor's WSL integration to open the Linux checkout instead.

## Verify a complete development loop

Confirm the runtime version inside Linux, install the project's dependencies, run its tests, then start its server. Test the URL from your browser and inspect the actual bind address if it is unreachable. Localhost forwarding and networking modes are configuration-dependent; do not assume LAN devices can connect.

## Back up before changing distributions

Back up source, ignored configuration, and local databases. WSL can export a distribution from PowerShell; replace `Ubuntu` with the exact name from the list:

```plaintext
wsl --export Ubuntu C:\Backups\ubuntu.tar
```

Create the destination directory first and stop database services for a consistent backup. An export is not verified until you have a recovery plan and have checked the archive.

<Highlight color="flame">The unregister command deletes a distribution and its data. It is not a routine restart or troubleshooting step.</Highlight>

Use `wsl --shutdown` when a full WSL restart is needed, after saving work; it stops all running distributions. Resource tuning should follow measured needs, not arbitrary limits copied from another machine.

<RainbowHighlight block>Treat WSL as a real Linux environment with its own dependencies, data, and recovery plan.</RainbowHighlight>

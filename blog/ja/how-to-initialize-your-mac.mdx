Macのリセットで失うものはアプリだけではありません。開発環境には未pushのコミット、無視された設定、DBボリューム、Gitから戻せない認証情報があります。

<Highlight color="flame">バックアップと、復元に必要なアカウントへのアクセスを確認するまで消去しないでください。</Highlight>

## 何を解決するのか決める

一つのプロジェクトの不調なら、まずその環境を調べます。譲渡や意図的な再構築なら「このMacについて」でモデルとmacOS版を確認します。会社や学校の管理端末は管理者の手順に従います。

復元後に必要なパスワード管理、各アカウント、代表的なアプリ、再作成できないデータを書き出します。これが完了条件になります。

## Gitだけでは戻せない作業を保存する

各リポジトリで確認します。

```bash
git status --short
git log --oneline --branches --not --remotes
```

二つ目はローカルのリモート追跡参照にないコミットを調べる助けになりますが、その参照自体が古い場合があります。意図するリモートでも確認します。作業ツリーがきれいでも、全データの保存を意味しません。

DBは専用のバックアップ機能でエクスポートします。Dockerボリューム、仮想マシン、`.env`、証明書、未同期素材も確認します。秘密情報は適切な非公開バックアップへ保存し、公開リポジトリへ入れません。

Homebrewなら一覧を作れます。

```bash
brew bundle dump --file="$HOME/Brewfile"
```

内容を確認して保管します。`.node-version`や`.python-version`なども記録します。全体のツール一覧だけでは各環境を再現できません。別端末からパスワード管理と二要素認証の復旧も確認します。

<Highlight color="lemon">代表的なファイルやデータを実際に復元してから、バックアップを信頼しましょう。</Highlight>

## 対応する消去方法を選ぶ

[Appleの「すべてのコンテンツと設定を消去」ガイド](https://support.apple.com/en-us/102664)は、Monterey以降の対応Appleシリコン・T2搭載Macを扱います。新しいmacOSは「システム設定→一般→転送またはリセット」、Montereyはシステム環境設定のメニューです。修理確認など、現在のガイドが示す前提も確認します。この方法はインストール済みOSを保ち、利用者のデータと設定を消去します。

利用できない場合はモデル別の復旧手順へ進みます。全機種で同じ形式やボリューム操作が適切とは仮定しません。[Intel向け消去ガイド](https://support.apple.com/en-us/102639)には手順の区別とAppleシリコン向けリンクがあります。内蔵の対象を確認し、バックアップドライブは消去しません。

<Underline>OSの再インストールと個人データの消去は別の操作です。</Underline> 再インストールだけで譲渡準備が済むとは考えず、Appleの譲渡手順に従います。必要なら設定アシスタントを受取人のために残します。

## 一つのプロジェクトを先に復元する

設定後はOSを更新し、信頼できる開発ツールと対象プロジェクトのランタイムを入れます。設定は選んで戻し、認証し、古いビルドキャッシュではなく依存関係を再作成します。

導入、テスト、ビルド、起動を確認し、DBや外部連携も別途試します。文書と同期を確認し、新しいバックアップを作ります。必要な実作業を確かめるまで以前のバックアップを残します。

<RainbowHighlight block>リセットの成功は空のデスクトップではなく、戻せるデータと再び動く環境で確認しましょう。</RainbowHighlight>

USキーボードでも日本語は入力できます。キーボード配列は物理キーと記号の対応を決め、入力メソッドは入力した文字を日本語へ変換します。一方を変えても、もう一方が自動的に整うわけではありません。

<Highlight color="lemon">配列は実物のキーボードに合わせ、日本語変換にはMozcを追加します。</Highlight>

## 先に物理配列を確認する

GNOMEを使うUbuntu Desktopでは、設定の「キーボード」から「入力ソース」を探します。版によっては「地域と言語」にあります。USならEnglish (US)、JISなら対応する日本語配列を追加し、プレビューと実際の入力で`@`、`:`、括弧などを確認します。

入力ソースと切り替えについては[Ubuntuの配列ガイド](https://help.ubuntu.com/stable/ubuntu-help/keyboard-layouts.html)も参照できます。GNOME以外のデスクトップでは設定画面や入力基盤が異なる場合があります。

## 入力メソッドを追加する

Japanese (Mozc)がない場合、Ubuntuのパッケージ管理からIBus用の連携をインストールします。

```bash
sudo apt update
sudo apt install ibus-mozc
```

ログアウトして再ログインし、日本語のMozcを入力ソースへ追加します。入力インジケーターで選択し、英字のままなら「ひらがな」モードに切り替えます。`nihongo`を入力し、Spaceで候補を選び、Enterで確定できるか試します。

USキーボードはUS配列のままMozcで変換できます。Mozcのときだけ記号の位置が変わるなら、システム全体をJISにする前に、入力メソッド側の配列設定を調べます。

## 症状を分けて調べる

| 症状 | 最初に確認すること |
| --- | --- |
| どのアプリでも記号がおかしい | 物理配列の選択 |
| Mozcなのに英字が出る | 直接入力とひらがなモード |
| Mozcが候補にない | インストールと再ログイン |
| 特定アプリだけ入力できない | アプリの入力メソッド対応 |

<Highlight color="flame">最初から/usr/share内のパッケージ管理ファイルを編集しないでください。更新で戻ることがあり、調査中の問題以外へも影響します。</Highlight>

KDEやFcitxを使う場合は、その環境の手順に従い、入力基盤を無計画に混在させません。パスワード入力や調査のため、正常に動く入力ソースも残します。変換できたら設定で切り替えキーを確認します。ショートカットは版やカスタマイズによって異なります。

サインイン画面の名前を変えても、`C:\Users`内のフォルダー名が変わるとは限りません。アプリ設定、タスク、開発環境などには、既にそのパスが保存されている場合があります。

<Highlight color="flame">使用中のプロファイルを直接改名したり、古いレジストリ回避策をWindows 10・11へ適用したりしないでください。Microsoftも旧手順をこれらの版で使わないよう注意しています。</Highlight>

[Microsoftのプロファイルパスに関する説明](https://learn.microsoft.com/en-us/previous-versions/troubleshoot/windows-client/renaming-user-account-not-change-profile-path)を確認してください。権限変更やプロセス停止だけでは、保存済みの全パスは直りません。新規アカウントへ移行し、確認する方が管理しやすい方法です。

## パス変更が本当に必要か

表示名だけを変えたいなら、フォルダーはそのままにします。開発ツールの問題なら、まずリポジトリを`C:\dev`などの単純な場所へ移して解決できないか調べます。

新しいプロファイルが必要なら、データをバックアップし、別の管理者アカウントでサインインできることを確認します。会社のPCでは組織の管理方針に従います。

## 新規作成してパスを確かめる

1. 設定の「アカウント」から他のユーザーを管理する画面を開きます。名称はWindowsの版で異なります。
2. 希望する簡単な名前でローカルアカウントを作ります。Microsoftアカウントの表示名から特定のパスになるとは仮定しません。
3. 一度サインインしてプロファイルを作成します。
4. PowerShellで`$env:USERPROFILE`を実行し、実際のパスを確認します。

<Underline>移行を始める前に、移行先が意図どおりか確かめます。</Underline> 新しい環境の確認中は、旧アカウントを残します。

## データと設定を分けて移す

プロファイル全体ではなく、文書やプロジェクトをコピーします。新しいレジストリファイルを上書きしたり、`AppData`を無条件で統合したりしません。設定はアプリのエクスポート機能を使い、必要なら再インストールします。クラウド保存先は同期状況を確認してから再接続します。

開発用の未コミットファイルや無視された設定も、安全に保管します。仮想環境は作り直し、依存関係を再インストールします。シェル設定やタスクに旧パスがないか確認してください。ファイルをコピーできても、内部に絶対パスが残ることがあります。

## 普段の作業ができるか確認する

文書を開き、プロジェクトを起動し、必要なサービスへのログインと同期を確かめます。アクセスできないファイルは所有者や権限を調べ、全員への権限付与で回避しません。旧アカウントの削除は別の破壊的操作なので、検証済みのバックアップを確保してから判断します。

<RainbowHighlight block>表示名だけなら名前を変え、保存先まで変えるなら新しいプロファイルへ移して検証しましょう。</RainbowHighlight>

「合計がおかしい」は報告であり、まだ原因ではありません。入力、期待値、実際の結果、最初に差が生まれる地点を絞り込みます。

## 具体的な失敗を記録する

画面やコマンド、入力、期待値、実際の結果、関連バージョンを記録します。例えば価格100と手数料20で120ではなく10020が出る、という形です。個人情報を含む場合は架空の値で再現します。

```js
function total(price, fee) {
  return price + fee;
}
console.log(total('100', 20)); // '10020'
```

型を見れば原因の候補が分かります。JavaScriptの`+`は文字列を連結することもあります。数値入力欄でもDOMの`value`は文字列で、数値を返す`valueAsNumber`は別のAPIです。

<Highlight color="lemon">最終表示だけでなく、最初に予想外の値になる場所を探しましょう。</Highlight>

## 仮説を否定できる実験をする

フォームの値が計算へ入る箇所で停止し、値と型を調べます。既に数値なら、この失敗を文字列連結では説明できません。最初の思い付きで直さず、データを追います。

0以上の整数だけを扱う例では、境界で明示的に検証できます。

```js
function parseAmount(value) {
  if (typeof value !== 'string' || !/^\d+$/.test(value.trim())) {
    throw new Error('Enter a whole non-negative amount');
  }
  const amount = Number(value);
  if (!Number.isSafeInteger(amount)) throw new Error('Amount too large');
  return amount;
}
console.log(parseAmount('100') + parseAmount('20')); // 120
```

小数や区切り文字は意図的に拒否しています。受け付ける形式の変更は仕様の判断です。型変換の規則は[加算演算子の説明](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/Addition)を参照してください。

## 元の失敗と周辺条件を確認する

元の入力、空文字、不正文字、0、範囲外を試し、元の不具合を回帰テストにします。表示が変わるからという理由で演算子を置き換えても、契約を満たす証拠にはなりません。

<Underline>原因に対する変更は一つずつ行います。</Underline> 同時に依存関係を更新し全キャッシュを消すと、何が効いたのか説明できなくなる場合があります。

## ときどきしか起きない場合

時刻とリクエスト識別子を記録し、成功時と失敗時を比較します。各通信は成功していても、古い応答が新しい結果を上書きすることがあります。本番に適当な待機時間を追加するより、応答を遅らせた再現例を作ります。

一時ログを片付け、必要な診断だけ残します。最後に、発生条件、原因、変更、確認結果を短くまとめます。他の開発者が問題と修正を再現できる状態が目標です。

<RainbowHighlight block>よい修正は、当てずっぽうの変更ではなく、検証した原因の説明から生まれます。</RainbowHighlight>

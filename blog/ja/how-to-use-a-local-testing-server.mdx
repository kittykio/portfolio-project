静的サーバーはファイルを配信し、モックAPIはテスト用データを返し、フレームワークの開発サーバーはアプリのコンパイルや実行も行います。用途を区別すると、実行できないツールを使って悩むことを避けられます。

## 静的ページを配信する

公開してよいデモファイルだけのフォルダーを作り、その中でPython 3を起動します。

```bash
python3 -m http.server 8080 --bind 127.0.0.1
```

Windowsでは`py -3`を使う環境もあります。`http://127.0.0.1:8080`を開きます。`index.html`があれば表示され、なければ一覧が出る場合があります。[Pythonの説明](https://docs.python.org/3/library/http.server.html)のとおり、これは本番用サーバーではありません。

<Highlight color="flame">ホームフォルダーや秘密情報を含むリポジトリではなく、専用のデモフォルダーを配信してください。静的サーバーは公開してはいけないファイルを判断できません。</Highlight>

`127.0.0.1`へのバインドは接続をこの端末に限定しますが、秘密情報を置いてよい理由にはなりません。スマートフォン自身のlocalhostからPCへ接続することもできません。

## 予測できるAPIを用意する

独立した教材用に、この例はJSON Server 0.17.4を指定します。新しい版とはCLIが異なるため、[対象版のREADME](https://github.com/typicode/json-server/tree/v0.17.4)を確認します。

`db.json`を作ります。

```json
{ "users": [{ "id": 1, "name": "Aki" }] }
```

次のコマンドで起動します。

```bash
npx json-server@0.17.4 --watch db.json --host 127.0.0.1 --port 8081
```

`http://127.0.0.1:8081/users`でAkiの配列が返ることを確認します。CRUDの練習には使えますが、本番の権限、トランザクション、入力検証を証明するものではありません。書き込みで変わるため、使い捨てのデータを使います。

## フレームワークには専用コマンドを使う

Next.jsやViteなどでは`package.json`を調べ、プロジェクトの開発スクリプトを使います。PythonのサーバーではTSXをコンパイルしたりNext.jsのルートを実行したりできません。8080の画面から8081のAPIを呼ぶ場合は異なるオリジンなので、CORSエラーはブラウザーの保護を無効化せず調べます。

<Highlight color="lemon">コードを変える前に、URL、期待する応答、サーバーの種類を確認しましょう。</Highlight>

## 使い終わったら停止する

フォアグラウンドのサーバーはCtrl–Cで止めます。ポートが使用中なら所有プロセスを確認するか別の番号を選び、無関係なプロセスをまとめて終了しません。表示が古い場合はNetworkパネルと再読み込みで確認します。

<RainbowHighlight block>用途に合うサーバーを選び、デモデータだけを配信し、作業後は停止しましょう。</RainbowHighlight>

A selector describes which elements a rule can reach. Before adding another class or a more specific override, inspect the relationship you are trying to express. These five selectors cover common component layouts without requiring JavaScript.

## Start with a small fixture

Put this markup in an HTML document and apply each rule below separately. Inspect the selected elements in your browser's developer tools.

```html
<section class="notes">
  <h2>Field notes</h2>
  <p>Introduction</p>
  <aside><p>Nested note</p></aside>
  <p data-state="important">Bring a notebook.</p>
  <ul><li>Map</li><li>Water</li><li>Camera</li></ul>
</section>
```

## Match a relationship, not an accident

```css
.notes > p { border-inline-start: 3px solid teal; }
.notes h2 + p { font-size: 1.2rem; }
.notes h2 ~ p { line-height: 1.8; }
.notes [data-state="important"] { font-weight: 700; }
.notes li:nth-child(odd) { text-decoration: underline; }
```

| Selector | Match in this fixture | Common misunderstanding |
| --- | --- | --- |
| `> p` | Introduction and notebook paragraphs | The nested note is a descendant, but not a direct child. |
| `h2 + p` | Introduction only | The next element sibling must be a paragraph. |
| `h2 ~ p` | Both outer paragraphs after the heading | Matching elements must share the heading's parent. |
| `[data-state="important"]` | Notebook paragraph | This tests an attribute value, not its visual appearance. |
| `li:nth-child(odd)` | Map and Camera | Positions count element siblings, starting at one. |

These relationships follow the [CSS selector and combinator definitions](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Selectors/Selectors_and_combinators). Whitespace and comments do not count as element siblings.

<Highlight color="lemon">Predict the matched elements before judging the visual result. Inherited styles can make an unselected child look selected.</Highlight>

## Check how the component changes

Insert a small description between the heading and introduction. The adjacent rule stops matching; the general-sibling rule still matches. Move the notebook paragraph inside the aside and it no longer matches the direct-child rule. These are useful experiments because they reveal which markup changes your styling depends on.

<Underline>Structure-dependent styling needs a stable structure.</Underline> For a card that can be rearranged freely, a descriptive class such as `.notes__intro` may communicate intent better than relying on position. Use an attribute when it represents real application state, and keep that state synchronized with any accessible label.

An unmatched selector and an overridden declaration are different problems. If a rule appears crossed out in developer tools, investigate the cascade. Increasing specificity will not fix a selector that points at the wrong relationship.

## Practice before reusing

Try an empty list, one list item, and a nested list. Scope selectors to the component that owns them. Do not use a color change alone to communicate an important state; retain readable text or another explicit cue.

<RainbowHighlight block>Choose the simplest selector that describes the relationship you intend to keep.</RainbowHighlight>

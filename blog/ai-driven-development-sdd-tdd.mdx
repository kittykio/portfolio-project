An assistant can implement a plausible feature before its requirements are clear. The remedy is a short feedback loop: write the intended behavior, test one observable case, and inspect the change that makes it pass.

## Give specifications and tests different jobs

Here, specification-driven development means maintaining an explicit description of behavior, constraints, and non-goals. Test-driven development means observing a behavior test fail before implementing the behavior, then refactoring while it stays green. A test written after the feature may be valuable, but it did not drive that implementation.

[GitHub Spec Kit](https://github.com/github/spec-kit) is one toolkit for organizing specification-driven work. You do not need it for this exercise. A short file is enough when everyone can review the contract.

<Highlight color="lemon">The specification defines the promise; tests provide evidence for selected examples of that promise.</Highlight>

## Build one feature through the feedback loop

Consider a portfolio post filter. Use a scratch directory with Node.js 24 for this example. The `.mjs` files use JavaScript modules, and the [built-in Node.js test runner](https://nodejs.org/api/test.html) runs the tests without installing a testing package.

### 1. Write a small specification

Save the following as `spec.md`:

```markdown
## Title filtering

- Input: an array of posts with string titles and a string query.
- Match a case-insensitive substring of each title.
- Ignore leading and trailing whitespace in the query.
- Return all posts when the trimmed query is empty.
- Preserve the input order and do not mutate the input array.
- Return an empty array when nothing matches.
- Non-goals: ranking, fuzzy search, pagination, and runtime validation.
```

This deliberately limits the search contract. Lowercasing is not a complete multilingual search strategy; accent handling and language-specific matching would need separate requirements. You can ask AI to point out such omissions, but decide which belong in this feature before expanding the scope.

### 2. Observe a meaningful failure

Create `filter-posts.mjs` with a deliberately incomplete implementation:

```js
export function filterPosts(posts, query) {
  return posts;
}
```

Create `filter-posts.test.mjs` with the first behaviour test:

```js
import test from 'node:test';
import assert from 'node:assert/strict';
import { filterPosts } from './filter-posts.mjs';

const posts = [
  { title: 'Testing JavaScript' },
  { title: 'CSS Layout' },
  { title: 'JavaScript Modules' },
];

test('matches titles case-insensitively and preserves order', () => {
  assert.deepEqual(filterPosts(posts, 'JAVASCRIPT'), [posts[0], posts[2]]);
});
```

Run:

```bash
node --test filter-posts.test.mjs
```

The assertion should fail because the stub returns the CSS post too. A missing module or syntax error would not demonstrate the intended missing behaviour; fix setup problems before treating the result as the red step.

### 3. Make the first test pass

Replace the stub with:

```js
export function filterPosts(posts, query) {
  const normalizedQuery = query.toLowerCase();
  return posts.filter((post) =>
    post.title.toLowerCase().includes(normalizedQuery)
  );
}
```

Run the same command again. Once it passes, add this test to the test file:

```js
test('ignores surrounding query whitespace', () => {
  assert.deepEqual(filterPosts(posts, '  javascript  '), [posts[0], posts[2]]);
});
```

Run it and observe the new failure. Then change the `normalizedQuery` line to:

```js
const normalizedQuery = query.trim().toLowerCase();
```

Run the tests again. This is a small, visible TDD loop: the new requirement has evidence of failure before its implementation.

### 4. Check the remaining contract

Append these regression checks and run the command once more:

```js
test('returns all posts for an empty or whitespace-only query', () => {
  assert.deepEqual(filterPosts(posts, ''), posts);
  assert.deepEqual(filterPosts(posts, '   '), posts);
});

test('returns no matches and handles an empty input', () => {
  assert.deepEqual(filterPosts(posts, 'Python'), []);
  assert.deepEqual(filterPosts([], 'JavaScript'), []);
});

test('does not mutate the input array or its posts', () => {
  const frozenPosts = Object.freeze([
    Object.freeze({ title: 'JavaScript Modules' }),
    Object.freeze({ title: 'CSS Layout' }),
  ]);
  const before = structuredClone(frozenPosts);
  filterPosts(frozenPosts, 'javascript');
  assert.deepEqual(frozenPosts, before);
});
```

These cases already pass with the current implementation. They add coverage; do not claim they each drove a code change. The returned array shares the original post objects, which is compatible with this specification: filtering does not mutate them, but it does not deep-clone them either.

There is no useful refactor to force into this tiny function. In a larger change, improve names or remove duplication, rerun the tests, and keep observable behaviour stable.

## Review the loop before increasing autonomy

The example covers a pure function with controlled inputs. A search interface also needs empty states, input events, and the connection between query state and displayed results. Do not claim the function tests validate that entire experience.

<Underline>Read the expectations independently of the implementation.</Underline> An assistant can repeat one mistaken assumption in both. Ask which incorrect output each assertion rejects, and whether an important requirement has no example.

<Highlight color="flame">A missing module is a setup failure, not the meaningful red test required by TDD.</Highlight>

For repository work, supply the relevant files, installed versions, scope, and verification command. Ask for actual results, not a prediction that tests should pass. Keep the task small enough to review its callers and failure paths. Compare total design, review, and rework time when deciding whether assistance helps.

<RainbowHighlight block>Make intent explicit, observe a meaningful failure, and verify the smallest change that satisfies it.</RainbowHighlight>

This site's blog loader reads MDX from `blog/` and its Japanese counterpart from `blog/ja/`. The filename connects the editions and contributes to the generated reaction ID. Keep an existing filename stable when revising an article.

## Keep the metadata contract small

```mdx
---
date: "2026-09-16"
title: "A specific article title"
description: "Explain what readers will learn or be able to do."
tags: ["MDX", "Documentation"]
image: "/blog/images/example.png"
---
```

Use the same date and image path in both editions. Localize title, description, and tag labels, but keep code behavior equivalent. The image URL omits `public`; the actual file belongs under `public/blog/images/`. Example paths in this guide illustrate syntax and do not create assets.

<Highlight color="lemon">The article page already supplies its title. Start body sections at heading level two.</Highlight>

## Use components for the roles they serve

Ordinary Markdown headings, lists, links, tables, and bold already pass through site renderers. Named components add editorial treatments. Use a lemon note for prerequisites, a flame note for a warning, and Underline for a short pivotal phrase instead of relying on bold for every kind of emphasis.

```mdx
<Highlight color="lemon">A concise prerequisite.</Highlight>
<Highlight color="flame">A concrete warning.</Highlight>
<Underline>A pivotal phrase.</Underline>
<RainbowHighlight block>The final practical takeaway.</RainbowHighlight>
<Divider />
```

Keep each text component's opening tag, text, and closing tag on one physical line. The browser wraps it visually. In particular, RainbowHighlight remains a span even with `block`; blank lines or nested paragraphs can create invalid HTML. Do not put these treatments inside headings or table cells, or stack them around the same words.

<Highlight color="flame">MDX is executable content. Publish reviewed, trusted source rather than treating arbitrary uploaded MDX as harmless text.</Highlight>

## Show structure only when it is a real structure

Use MDXFileTree for directories, not abstract lists of careers or benefits. The loader strips JavaScript-valued props by default, so pass a named preset rather than an inline array. Add new tree data to the preset map in application code; each node needs a unique ID, a name, and a file/folder type. This site's named example preset is:

<MDXFileTree preset="authoringGuide" />

```mdx
<MDXFileTree preset="authoringGuide" />
```

For supporting assets, use `Img` with a real `src`, localized `alt`, and accurate width/height. Use `FileLink` only for an actual downloadable file. Awkward, Spacey, Playful, Saucy, and Loud are optional font treatments; Sparkly is an animated effect. These are treatments for short expressive phrases; essential instructions should remain easy to read. Do not invent component names or import them into each article.

## Choose tags for discovery

Pick one to three reusable subjects that the body actually teaches. `AI` and `Career` fit an AI employment discussion better than a generic `Web Development` tag. Reuse exact spelling: matching and filtering use strings, not inferred synonyms.

Earlier and next related navigation selects articles sharing a tag and orders them by date. A newest related article may have no next article. Tags should describe content, not be added merely to fill both navigation slots.

## Validate the reading experience

Compile both editions with the blog's actual MDX pipeline. Check closed JSX tags, code fences, image paths, localized internal links, and the table of contents. Open each language at a narrow width and inspect long code and highlighted text. Keep warnings factual and place the required final RainbowHighlight after references, as the last body element.

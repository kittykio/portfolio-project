A file can have several timestamps, and copying it between filesystems may change some of them. Before editing a date, decide whether you mean file creation, content modification, or a date embedded inside the document, such as photo metadata.

<Highlight color="flame">Practice on a disposable copy. Filesystem timestamps are not a reliable audit history, and changing them does not rewrite dates embedded in the file.</Highlight>

## Inspect macOS metadata first

The macOS version of `stat` uses BSD-style options. For a file named `sample.txt`:

```bash
stat -f 'Created: %SB | Modified: %Sm | Metadata changed: %Sc' -t '%Y-%m-%d %H:%M:%S %z' sample.txt
```

The metadata-change time is not the creation time. To set the modification time to a local clock value, use:

```bash
touch -mt 202509141530.00 sample.txt
```

This can create a file if the path does not exist, so check the filename first. It is not a general creation-time editor.

## Creation time on macOS depends on available tools

Some Xcode Command Line Tools installations provide `SetFile`. Check availability before relying on it:

```bash
xcrun --find SetFile
```

If present, inspect `SetFile -h` and its local manual for the installed version. On versions supporting the documented date option:

```bash
SetFile -d '09/14/2025 15:30:00' sample.txt
```

Then rerun `stat`. `SetFile` is an older developer utility; do not assume every Mac includes it or that installing developer tools is necessary for a simple modification-time change. The installed `man stat` and `man touch` are the authoritative references for this machine's flags.

## Use an explicit timezone in PowerShell

For a disposable Windows file, the UTC property avoids ambiguous local date interpretation:

```plaintext
$file = Get-Item -LiteralPath 'C:\Temp\sample.txt'
$instant = [DateTimeOffset]::Parse('2025-09-14T15:30:00+09:00')
$file.CreationTimeUtc = $instant.UtcDateTime
$file.Refresh()
$file | Format-List CreationTimeUtc,LastWriteTimeUtc,LastAccessTimeUtc
```

`LastWriteTimeUtc` is a separate property if the modification time is what you need. [Microsoft documents CreationTimeUtc](https://learn.microsoft.com/en-us/dotnet/api/system.io.filesysteminfo.creationtimeutc); actual precision and behavior depend on the filesystem.

<Highlight color="lemon">Verify the field you changed with a fresh read, including its timezone, instead of trusting a file manager's display alone.</Highlight>

Keep the original copy until the consuming application behaves as expected. Sync tools, archives, and exports may preserve different fields, so test the full transfer path when timestamps are part of a workflow.

<RainbowHighlight block>Identify the date's meaning, change only the intended field, and verify it after every relevant transfer.</RainbowHighlight>

Dark mode is a set of relationships: readable text on a surface, visible focus beside a control, and enough separation to understand grouped content. Changing the page background alone leaves those relationships unresolved.

<Highlight color="lemon">Define a color's responsibility before choosing its value.</Highlight>

Use semantic tokens for canvas, card, text, muted text, border, link, and focus. A component should consume those roles rather than inventing its own theme exceptions. This standalone example uses the portfolio's palette but does not replace its theme controller.

## Build a small theme contract in CSS

Save the following as `theme.css`. Light is the default; setting `data-theme="dark"` on the document element selects the dark values.

```css
:root {
  color-scheme: light;
  --canvas: #ffffff;
  --card: #e6e6e6;
  --text: #292929;
  --text-muted: #505050;
  --border: #8b8b8b;
  --link: #8c280d;
  --focus: #8c280d;
}

:root[data-theme="dark"] {
  color-scheme: dark;
  --canvas: #2c2522;
  --card: #2d2926;
  --text: #e6e6e6;
  --text-muted: #bababa;
  --border: #8b8b8b;
  --link: #eb7858;
  --focus: #e8ff38;
}

body {
  margin: 0;
  padding: 2rem;
  background: var(--canvas);
  color: var(--text);
  font-family: system-ui, sans-serif;
  line-height: 1.6;
}

.card {
  max-width: 36rem;
  padding: 1.5rem;
  background: var(--card);
  border: 1px solid var(--border);
  border-radius: 1rem;
}

.card p { color: var(--text-muted); }
.card a { color: var(--link); text-underline-offset: 0.2em; }
.card a:focus-visible {
  outline: 3px solid var(--focus);
  outline-offset: 4px;
}
```

Use this complete `index.html` beside the stylesheet:

```html
<!doctype html>
<html lang="en" data-theme="dark">
  <head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>Theme study</title>
    <link rel="stylesheet" href="theme.css">
  </head>
  <body>
    <main>
      <article class="card">
        <h1>A place for useful ideas</h1>
        <p>Read practical notes on building and testing web interfaces.</p>
        <a href="https://kittykio.com/blog">Explore the blog</a>
      </article>
    </main>
  </body>
</html>
```

Open it in a browser, then change the attribute to `data-theme="light"` and reload. The component rules stay the same; their inputs change. Press Tab to inspect the link's focus outline in both editions.

The [`color-scheme` property](https://drafts.csswg.org/css-color-adjust-1/#color-scheme-prop) tells the browser which scheme an element supports, affecting browser-provided UI such as controls and scrollbars. It does not rewrite every authored colour. Your tokens still define the card, text, and link styling.

## Measure pairs, not individual swatches

A brand colour is not intrinsically accessible. Its contrast depends on the background and the role it plays. The table below uses opaque, flat sRGB colours from this portfolio's palette, calculated with the WCAG relative-luminance formula and rounded to two decimals for display.

| Foreground | Background | Contrast | Normal text at AA |
| --- | --- | --- | --- |
| Flame 500 `#CB4625` | White `#FFFFFF` | 4.73:1 | Pass |
| Flame 500 `#CB4625` | Cocoa 900 `#2C2522` | 3.18:1 | Fail |
| Flame 300 `#EB7858` | Cocoa 900 `#2C2522` | 5.28:1 | Pass |
| Gray 300 `#BABABA` | Cocoa 900 `#2C2522` | 7.76:1 | Pass |
| Gray 500 `#8B8B8B` | White `#FFFFFF` | 3.41:1 | Fail |
| Gray 100 `#E6E6E6` | Cocoa 700 `#2D2926` | 11.55:1 | Pass |

[WCAG 2.2's text-contrast guidance](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) sets a 4.5:1 minimum for normal text at level AA and 3:1 for large text, with specified exceptions. Large text means at least 18 points, or 14 points bold, approximately 24 CSS pixels or 18.7 CSS pixels bold. Use the unrounded ratio when determining a pass.

The orange that works on white does not meet the normal-text threshold on the dark canvas. That is why a theme can keep its brand identity while assigning a lighter orange to dark-mode links. Also test the actual card background; a canvas measurement cannot validate every surface.

<Highlight color="flame">A passing colour pair does not make a whole component accessible. Check its size, states, background, and interaction too.</Highlight>

For translucent surfaces or gradients, inspect the final composited background behind the content. A token's hex value alone does not describe that result. Screenshots help find suspicious regions, while contrast tools help measure the specific pair.

## Design focus, errors, and selection as part of the theme

An interface has more states than its default screenshot shows. Review hover, focus, active, selected, error, loading, and disabled states wherever they exist. Make sure a focused link remains visible on both the canvas and a card.

[WCAG's non-text contrast guidance](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html) requires 3:1 contrast against adjacent colours for visual information needed to identify many controls and states, with exceptions. It does not require every decorative separator or card edge to meet that ratio. First identify what information the visual element communicates.

Keep visible keyboard focus, as described in [the focus-visible guidance](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html), and check that outlines are not clipped by surrounding overflow. The example uses an offset outline and retains the link's underline; colour is not its only cue.

Likewise, pair an error colour with a useful message, and distinguish selection with a label, icon, or structural change where appropriate. [WCAG's use-of-colour guidance](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html) explains why colour alone should not carry essential information.

## Check assets and hierarchy in context

Temporarily remove decorative shadows. Can you still see which elements belong together? On dark surfaces, a restrained border and spacing often communicate grouping more clearly than a black shadow. Do not reduce opacity on a whole card to mute one label; that also reduces contrast for controls and body text.

Inspect transparent logos, photographs, covers, and syntax colors separately. A global inversion filter can distort photographs or make a screenshot misleading. Measure comments and punctuation on the actual code-block background, not only bright keywords.

<Underline>One theme controller should own the user's preference.</Underline> Honor an explicit selection; use the system setting when the user chooses System. A saved copy of yesterday's system preference is not ongoing system tracking. In a server-rendered app, check the first paint and hydration because the server cannot read browser local storage directly.

## Use a repeatable review page

Keep a representative page containing text, links, a card, an image, and form states. Review both themes at a narrow width and with zoom. Navigate by keyboard, trigger errors, reload a saved preference, and change the system theme while System is selected.

Automated contrast checks help, but they do not establish that feedback is understandable or the page hierarchy is coherent. Record the specific failing pair or state so the fix can be verified in both themes.

<RainbowHighlight block>A coherent dark mode preserves readable relationships and usable states, not just familiar colors.</RainbowHighlight>

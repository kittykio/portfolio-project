A layout that looks good with three short titles may fail with a long URL or a narrow viewport. Start with rules that handle content growth, then add decoration.

## Use one small layout

Place a `.cards` container inside `main`, then add several `article` elements with class `card`, each containing an `h2`, a paragraph, and a real link. An image is optional. Apply this stylesheet:

```css
*, *::before, *::after { box-sizing: border-box; }
body { margin: 0; font-family: system-ui, sans-serif; line-height: 1.6; }
main { width: min(70rem, calc(100% - 2rem)); margin-inline: auto; }
.cards { display: grid; gap: 1rem; grid-template-columns: repeat(auto-fit, minmax(min(100%, 16rem), 1fr)); }
.card { min-width: 0; padding: 1rem; border: 1px solid #666; border-radius: 0.75rem; }
.card h2 { overflow-wrap: anywhere; }
.card img { display: block; max-width: 100%; height: auto; }
a { color: #174fa3; text-underline-offset: 0.2em; }
a:focus-visible { outline: 3px solid #174fa3; outline-offset: 3px; }
@media (prefers-reduced-motion: no-preference) {
  a { transition: color 150ms ease; }
}
a:hover { color: #70248a; }
```

`border-box` makes declared dimensions include padding and borders. The outer container leaves a margin while capping its width. The nested `min()` in the grid minimum allows a card to shrink below 16rem when the available space is narrower.

## Keep typography connected to preferences

Leave the root font size at its normal browser setting unless the design has a reason to change it. Relative spacing and unitless line height make it easier to adapt. Setting the root to 62.5% does not universally mean 10px; that assumption depends on the user's base size and can shrink text if you forget to compensate.

Long tokens need a wrapping strategy, but ordinary paragraphs should not be forced into arbitrary word breaks. The example limits `overflow-wrap: anywhere` to card headings; expand it only where the content requires it.

## Treat interaction as part of styling

The links remain underlined and have a visible keyboard outline. Hover is additional feedback, not the only sign that something is interactive. The short transition is enabled only when reduced motion is not requested; see the [media-feature reference](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion).

<Underline>Layout correctness includes the states people use.</Underline> Test focus and text selection as well as the default screenshot. Keep images proportional, supply HTML dimensions for real assets, and verify their alternative text.

## Try content that challenges the rules

Add a long title, a long URL, Japanese text, and a card without an image. Resize down to a narrow screen, increase text size, and tab through the links. Inspect any horizontal overflow rather than hiding it globally; `overflow-x: hidden` can conceal the symptom while clipping content or focus.

Only after these cases work should you add shadows or motion. Decoration is easier to tune when the underlying sizing remains predictable.

A language button is only the visible part of a bilingual blog. The underlying system must connect article identity, translated content, routes, and search metadata. This case study describes the current portfolio, with focused examples rather than a complete starter application.

## Separate article identity from language

A title is editorial copy. A slug connects a published article to its URL and, in this project, its reaction record. Translating the title should not create a different article identity.

The content layout follows this pattern. `hello-world` is an illustrative slug:

<MDXFileTree preset="bilingualBlog" />

Both MDX files represent one article. Their shared image is served at `/blog/images/hello-world.png`, without `public` in the URL. The public post routes are `/blog/post/hello-world` and `/ja/blog/post/hello-world`.

This site discovers its article list from the top level of `blog/`, then chooses content by locale. Consequently, a Japanese-only file does not become a new listed post. That is a deliberate limitation of an English-first catalogue; a site with independently published editions would need discovery across all locales.

<Highlight color="lemon">Keep the filename stable across languages. Localize the content that readers see.</Highlight>

## Follow the loader that actually renders posts

The loader in `src/lib/blogApi.ts` uses `compileMDX` from `next-mdx-remote/rsc`, with frontmatter parsing, GitHub-flavored Markdown, syntax highlighting, and heading extraction. Configuring imported MDX through `@next/mdx` does not automatically configure this separate pipeline.

Frontmatter contains date, title, description, tags, and image. TypeScript's generic frontmatter type does not validate authored YAML at runtime; publishing checks must verify the values and assets. The catalogue ignores hidden files and non-MDX entries so Finder metadata cannot turn into a nonexistent article path.

<Highlight color="flame">MDX is trusted executable source. Review its authorship and compilation path rather than accepting arbitrary user uploads.</Highlight>

## Preserve the component contract

The installed `next-mdx-remote` 6 pipeline strips JavaScript expressions by default. An inline tree array can compile and still lose its prop. This article uses `preset="bilingualBlog"`, which resolves reviewed tree data in application code. Keep literal props in authored content and inspect rendering, not just syntax. The [package documentation](https://github.com/hashicorp/next-mdx-remote) describes its rendering options.

Both languages should use the same component roles. A warning should warn about the same operation, and code examples should teach the same behavior. Translate explanatory text and image descriptions naturally; do not reduce the Japanese edition to a summary of the English tutorial.

<Underline>Shared identity does not require identical prose, but it does require equivalent information.</Underline>

## Distinguish translation from fallback

This loader falls back to English when a Japanese file is absent. That keeps a URL reachable, but does not make the content translated. The current metadata checks translation availability, uses the English canonical for an untranslated fallback, and only advertises existing language editions. The sitemap now includes both available editions and their language alternatives.

The site also derives the initial document language from the request locale. A future fallback notice could make an English body on a Japanese route clearer; that is separate from the metadata already implemented. Do not describe an unimplemented notice as existing behavior.

[Google's localized-page guidance](https://developers.google.com/search/docs/specialty/international/localized-versions) explains reciprocal language alternatives. Check the rendered links on both pages rather than assuming a language switcher creates those tags.

## Verify the complete pair

Keep filenames, original publication dates, and shared image paths aligned. Confirm localized titles, descriptions, and meaningful corresponding tags. In this app, tags are exact strings, so inconsistent spelling affects filtering and related-post matching.

Compile both files with the real loader, verify file trees receive their data, and open both URLs directly. Follow internal links, switch language on the same article, and inspect the initial HTML language and canonical. A reading-time estimate based only on whitespace remains a rough fit for Japanese; do not present it as a precise measure.

Resetting a Mac removes more than installed applications. A developer's working state can include unpushed commits, ignored configuration, database volumes, and credentials that are not recoverable from a Git remote.

<Highlight color="flame">Do not erase the Mac until the backup and the account access needed to restore it have both been verified.</Highlight>

## Decide what problem the reset solves

For a single broken project, start with that project's environment instead of erasing the computer. For transfer to a new owner or a deliberate clean rebuild, identify the Mac model and macOS version in About This Mac. A managed work or school device should follow its administrator's process.

Write down what must work afterward: a password manager, required accounts, a representative application, and any local data that cannot be recreated. This gives the reset an acceptance checklist.

## Preserve work that Git does not cover

For each active repository:

```bash
git status --short
git log --oneline --branches --not --remotes
```

The second command helps find commits not represented in your local remote-tracking references; those references may be stale. Inspect the repository and verify the intended remote separately. A clean worktree is not proof that everything is backed up.

Export local databases using their own backup tools. Review Docker volumes, virtual machines, ignored `.env` files, local certificates, and unsynced assets. Store secret material in an appropriate private backup, never a public repository.

For Homebrew users, a package inventory can help:

```bash
brew bundle dump --file="$HOME/Brewfile"
```

Review it before copying it to the backup. Record project runtime files such as `.node-version` or `.python-version`; a global tool list does not reproduce every project. Confirm password-manager access and two-factor recovery from another device.

<Highlight color="lemon">Test restoration of representative files and data before trusting the backup.</Highlight>

## Choose the supported erase route

Apple's [Erase All Content and Settings guide](https://support.apple.com/en-us/102664) covers supported Apple-silicon and T2 Macs with macOS Monterey or later. On newer macOS versions the entry is under System Settings → General → Transfer or Reset; Monterey uses the System Preferences menu. Follow the current guide for model-specific prerequisites, including any repair checks it lists. This process keeps the installed operating system while removing user data and settings.

If that route is unavailable, use the model-specific Recovery instructions. Do not assume the same Disk Utility format and volume steps apply to every Mac. Apple's [Intel erase guide](https://support.apple.com/en-us/102639) distinguishes that procedure and links to the Apple-silicon route. Confirm the selected internal volume; never erase the drive holding your backup.

<Underline>Reinstalling macOS and erasing personal data are different operations.</Underline> Reinstallation alone is not a reliable way to prepare a computer for a new owner. Follow Apple's ownership-transfer steps and leave Setup Assistant for the recipient when applicable.

## Rebuild one working project first

After setup, install system updates, trusted development tools, and the runtimes required by one representative project. Restore configuration selectively, authenticate to the necessary services, and recreate dependencies rather than copying old build caches.

Verify that the project installs, tests, builds, and starts; confirm its database and external integrations separately. Open restored documents, check sync completion, and create a fresh backup. Keep the old backup until you have verified the workflows you actually need.

<RainbowHighlight block>A successful reset is demonstrated by recoverable data and a working restored environment, not just an empty desktop.</RainbowHighlight>

A branch label is useful only if it changes when you change branches. A common prompt mistake evaluates a helper while assigning the prompt, leaving the original branch displayed until the configuration is reloaded.

## Identify the shell first

A terminal application can run zsh, Bash, or PowerShell. Their prompt syntax is different. The example below is specifically for zsh, commonly used on macOS. If a theme or prompt framework already owns your prompt, configure that tool rather than adding a second competing definition.

Back up `.zshrc` before editing and keep a working terminal open so you can remove the change if it causes trouble.

## Add a branch-only indicator

```bash
# zsh: add to ~/.zshrc after backing it up
setopt PROMPT_SUBST
branch_label() {
  local branch
  branch=$(git symbolic-ref --quiet --short HEAD 2>/dev/null) || return
  branch=${branch//\%/%%}
  print -r -- " ($branch)"
}
PROMPT='%n@%m %~$(branch_label) %# '

```

The outer single quotes defer `$(branch_label)` until prompt rendering. `PROMPT_SUBST` enables that expansion. The helper quietly returns nothing outside a repository or in detached HEAD state, and doubles percent signs because zsh interprets percent sequences in prompts.

<Highlight color="lemon">Use delayed evaluation so the branch is recomputed for each prompt, not just when the configuration loads.</Highlight>

The command is read-only. It does not fetch remote updates or tell you whether the worktree is clean. See [Git's symbolic-ref documentation](https://git-scm.com/docs/git-symbolic-ref) for the difference between a symbolic branch reference and detached HEAD.

## Test the states you rely on

Open a new zsh session, enter a repository, and confirm the label. In a disposable repository, switch between two existing branches and check that the next prompt updates. Leave the repository and confirm the label disappears. A missing label in detached HEAD is intentional in this minimal example; use a full prompt helper if you want a commit identifier there.

<Underline>A prompt is a reminder, not an approval to commit.</Underline> Run `git status` before a commit or push when the repository state matters.

## Bash and PowerShell alternatives

For Bash, Git ships a [git-prompt helper with setup instructions](https://github.com/git/git/blob/master/contrib/completion/git-prompt.sh). Locate the installed file rather than assuming a Homebrew or Linux path. Follow its quoting and prompt-command examples; copying the zsh snippet into `.bashrc` will not work.

For PowerShell, choose its native prompt function or a maintained prompt module and follow that module's documentation. Avoid stacking it with an existing theme. Keep Git checks lightweight: expensive status scans on every prompt can make large repositories feel slow.

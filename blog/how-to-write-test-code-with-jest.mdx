A useful first test answers a small, precise question. Here, a discount is an integer percentage from 0 to 100, and a price is a non-negative integer number of cents. We will test that contract rather than whether a function returns something truthy.

## Set up an isolated example

In a new directory, use a Node.js version supported by your chosen Jest release:

```bash
npm init -y
npm install --save-dev jest
npm pkg set scripts.test="jest"
```

These examples use CommonJS `.cjs` files and Jest's default discovery naming. Existing ESM, TypeScript, and React projects need the transformation or framework configuration described in the [Jest setup guide](https://jestjs.io/docs/getting-started); installing type definitions alone does not compile TypeScript.

## Give the function a contract

Save `discount.cjs`:

```js
function discountedCents(cents, percent) {
  if (!Number.isInteger(cents) || cents < 0 ||
      !Number.isInteger(percent) || percent < 0 || percent > 100) {
    throw new RangeError('Invalid price or percentage');
  }
  return Math.round(cents * (100 - percent) / 100);
}
module.exports = { discountedCents };
```

This is a small exercise, not a complete financial calculation policy. A real billing system needs explicit currency, rounding, and numerical-range requirements.

Create `discount.test.cjs`:

```js
const { discountedCents } = require('./discount.cjs');

test.each([[1000, 10, 900], [999, 50, 500], [1000, 100, 0]])(
  'discounts %i cents by %i percent to %i',
  (price, rate, expected) => {
    expect(discountedCents(price, rate)).toBe(expected);
  }
);

test('rejects a negative price', () => {
  expect(() => discountedCents(-1, 10)).toThrow(RangeError);
});
```

Run `npm test -- --runInBand`. The expected values are explicit, including a rounding boundary. A test for an exception passes a function to `expect`; calling the function before `expect` would throw outside the matcher.

<Highlight color="lemon">Choose fixtures that separate correct behavior from plausible mistakes, including boundaries and rejected inputs.</Highlight>

## Await asynchronous assertions

For an async function `loadUser` imported from your application, an assertion should await or return its promise:

```js
// Pattern only: supply your application's loadUser implementation.
test('reports a missing user', async () => {
  await expect(loadUser('missing')).rejects.toThrow('Not found');
});
```

<Highlight color="flame">Do not mock loadUser itself and then claim its behavior is tested. Mock an external dependency when needed, and call the real function under test.</Highlight>

For UI, assert visible results and interactions. A snapshot can detect output changes, but accepting a new snapshot without inspection can preserve a regression. Finish by temporarily changing one result in a scratch copy and confirming the relevant assertion fails, then restore it.

<RainbowHighlight block>A useful Jest test checks an independent expected outcome and fails when the behavior is wrong.</RainbowHighlight>

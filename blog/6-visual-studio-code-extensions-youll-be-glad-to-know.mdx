An extension is useful when it removes a problem you actually have. Install one at a time so you can identify whether it improves feedback, duplicates an existing feature, or introduces noise.

## Match the extension to a job

The links below point to the publishers' extension pages, where you can check current compatibility and configuration.

| Extension | Useful for | Check before enabling |
| --- | --- | --- |
| [Error Lens](https://marketplace.visualstudio.com/items?itemName=usernamehw.errorlens) | Bringing existing diagnostics beside the code | It displays diagnostics; it does not replace a language server or linter. |
| [GitLens](https://marketplace.visualstudio.com/items?itemName=eamodio.gitlens) | Exploring history and blame | Start with built-in Git; feature availability and account requirements vary. |
| [Path Intellisense](https://marketplace.visualstudio.com/items?itemName=christian-kohler.path-intellisense) | Completing paths in supported contexts | Test whether built-in language completion already handles your files. |
| [Prettier](https://marketplace.visualstudio.com/items?itemName=esbenp.prettier-vscode) | Consistent formatting | Use the project's formatter version and configuration. |
| [ESLint](https://marketplace.visualstudio.com/items?itemName=dbaeumer.vscode-eslint) | Showing configured JavaScript/TypeScript lint findings | The project needs an appropriate ESLint setup. |
| [Live Server](https://marketplace.visualstudio.com/items?itemName=ritwickdey.LiveServer) | Reloading a static HTML preview | Framework applications need their own development server. |

<Highlight color="lemon">Choose tools by the feedback they add, not by the number of extensions in your sidebar.</Highlight>

## Separate formatting from analysis

Prettier decides presentation; ESLint checks the configured code rules. Overlapping formatting rules can create edits that alternate on every save. Agree on one formatter and compatible lint rules before enabling both save actions.

For a team using Prettier, `.vscode/settings.json` can make the choice explicit:

```json
{
  "[javascript]": {
    "editor.defaultFormatter": "esbenp.prettier-vscode",
    "editor.formatOnSave": true
  }
}
```

This only configures JavaScript files. Add other language IDs deliberately and follow the repository's conventions rather than imposing a personal setup on every file.

## Verify before sharing settings

Open a representative file, introduce a harmless formatting difference, save, and inspect the diff. Then create a known lint violation and check whether both editor and command-line lint report it. If results differ, inspect the extension output and selected workspace version.

<Highlight color="flame">Treat extension installation and workspace trust as code-execution decisions. Check the publisher and avoid enabling unfamiliar repository tasks just to dismiss a prompt.</Highlight>

VS Code's [extension management documentation](https://code.visualstudio.com/docs/configure/extensions/extension-marketplace) covers installation and workspace controls. Keep workspace recommendations separate from personal themes and key bindings. Disable an extension temporarily when diagnosing editor slowdown before blaming the project itself.

<RainbowHighlight block>A small, understood editor setup is more useful than a large collection of overlapping automation.</RainbowHighlight>
